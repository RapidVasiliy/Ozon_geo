# ozon-geo — какие категории товаров уходят в какие города

Загружает отправления продавца из Ozon Seller API (FBS/rFBS и FBO), хранит их в SQLite и считает
матрицу «категория × город». Заложена основа под предиктивную аналитику (недельная панель + бейзлайн-прогнозы).

## Запуск одним файлом (без Jupyter)
```bash
pip install -r requirements.txt            # один раз: pandas, requests, openpyxl, matplotlib
python run_ozon_geo.py                     # API, с 2022-01-01 до сегодня (ключи спросит или возьмёт из OZON_CLIENT_ID/OZON_API_KEY)
python run_ozon_geo.py --since 2023-10-01 --to 2024-10-01
python run_ozon_geo.py --source csv --csv "orders/*.csv"
python run_ozon_geo.py --source db         # пересобрать отчёты из ozon.db без загрузки
```
Ключи можно положить в файл `.env` рядом со скриптом (в git он не попадает):
```
OZON_CLIENT_ID=123456
OZON_API_KEY=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```
Если консоль не принимает скрытый ввод ключа (Git Bash, консоли некоторых редакторов) — `--visible-key` или `.env`.
Результат в `out/`: `clusters_by_month.xlsx` (вкладка = кластер, строки = SKU, столбцы = месяцы), `ozon_geo.xlsx`,
графики PNG и PDF. Настройки по умолчанию — в начале файла `run_ozon_geo.py`.

## Ноутбук (интерфейс)
```bash
pip install -e ".[notebook]"
mkdir orders            # сюда положите выгрузки из кабинета (папка в .gitignore: там персональные данные)
jupyter lab ozon_geo.ipynb
```
В ноутбуке: параметры источника (`csv` / `api` / `demo`) -> загрузка -> отчёт с выпадающими списками (SKU, артикул, категория;
кластер или город; штуки, заказы, выручка; период; только доставленные) -> тепловая карта и динамика по неделям ->
базовая потребность по кластерам на N недель -> бэктест -> экспорт в `out/ozon_geo.xlsx`.
Несколько выгрузок читаются сразу (`orders/*.csv`), пересечения дублей не создают: берётся самая свежая выгрузка.
Источник можно задать и переменными окружения `OZON_GEO_SOURCE`, `OZON_GEO_CSV` (для запуска без интерфейса).

## Быстрый старт без API: CSV из личного кабинета
```bash
ozon-geo import-csv postings_jul.csv postings_aug.csv postings_sep.csv   # отчёт по отправлениям из ЛК
ozon-geo report --level sku --geo cluster          # SKU × кластер доставки
ozon-geo report --level offer --geo city           # артикул × город
ozon-geo categories categories.csv                 # необязательно: «Артикул»;«Категория» -> разрез по категориям
ozon-geo report --level category --geo cluster
```
Формат: разделитель `;`, кодировка UTF-8 или Windows-1251. Нужны колонки «Номер отправления», «Принят в обработку»,
«SKU», «Количество», «Кластер доставки», «Город доставки» (остальные — по возможности). Персональные данные
покупателя (имя, email, телефон, адрес) не читаются и не сохраняются. В отчёте нет категорий — их задаёт
файл `categories`. Время в отчёте кабинета — UTC (сверено с API: совпадает с `in_process_at`), месяцы, недели и фильтры по датам считаются по Москве; «Оплачено покупателем» — цена за штуку (проверено на реальной выгрузке: отношение к «Предельной цене» одинаково при количестве 1 и >1), выручка = цена × количество;
отменённые (статус «Отменён» или заполнена «Дата отмены») в отчёты не попадают.

## Быстрый старт через API
```bash
pip install -e ".[dev]"

# без ключей, на синтетических данных
ozon-geo demo && ozon-geo report && ozon-geo forecast

# с реальными данными (ЛК Ozon -> Настройки -> API-ключи)
export OZON_CLIENT_ID=... OZON_API_KEY=...
ozon-geo sync --days 180            # или --since 2026-01-01 --to 2026-06-30; по умолчанию только FBS, FBO: --schemes fbs fbo
ozon-geo report --level category    # или type (тип товара), sku, offer (артикул); --metric revenue
ozon-geo report --geo cluster       # по кластерам Ozon (для планирования остатков FBO)
```
Результаты в `out/`: `category_city.csv` (штуки, заказы, выручка, `share_in_category`, `lift`),
`matrix_<metric>.csv`, `top_cities_per_category.csv`, `weekly_panel.csv`, `forecast.csv`.

`lift` > 1 — город покупает категорию заметно чаще, чем в среднем по вашим продажам.
Отменённые отправления по умолчанию исключаются (`--include-cancelled`).

## Устройство
| Модуль | Роль |
|---|---|
| `client.py` | API: `/v4/posting/fbs/list` (v3 отключён 31.08.2026; постранично по `cursor`), `/v2/posting/fbo/list`, `/v3/product/info/list`, `/v1/description-category/tree`; окна по 30 дней, пагинация, ретраи на 429/5xx |
| `store.py` | SQLite; загрузка идемпотентна (повторный `sync` не плодит дубли) |
| `sync.py` | отправления -> категории по `offer_id` -> названия категорий |
| `analytics.py` | категория × город, топ городов, `weekly_panel` |
| `forecast.py` | интерфейс `Forecaster`, `MovingAverage`, `SeasonalNaive`, `backtest` (WAPE/MAE) |
| `demo.py` | синтетика с заложенными склонностями городов и сезонностью |

## Путь к предиктивной аналитике
1. Накопить ≥ 1–2 года истории (сезонность): `sync` с большим `--days` по кварталам.
2. Модель реализует `fit(panel)` / `predict(horizon)` и сравнивается с бейзлайнами через `backtest`
   (временное разбиение, без утечки будущего). Кандидат: CatBoost по панели с признаками города/категории,
   лагов, недели года, праздников, цены/акций.
3. Дополнительные источники: остатки по складам, реклама, цены конкурентов, демография города.

## Куда уехал товар: город или кластер
`--geo city` — город доставки (`analytics_data.city`, это город покупателя, не склада отправки).
`--geo cluster` — кластер доставки (`financial_data.cluster_to`); остатки FBO планируются по кластерам,
поэтому для наполнения складов этот разрез надёжнее. Склад/кластер отправки хранятся отдельно
(`warehouse`, `cluster_from`) и в «куда» не попадают. В выходных CSV колонка называется `destination`.
Старые БД мигрируют автоматически, но кластеры появятся только после повторного `sync` за нужный период.

## Ограничения
- Город берётся из `analytics_data` отправления, кластер — из `financial_data` (названия полей взяты из документации по памяти, проверьте на реальном ответе); Ozon может не отдавать его для части схем/статусов —
  такие строки попадают в «(не определён)». Проверьте долю таких строк на своих данных.
- Тело запроса `/v4/posting/fbs/list` сверено с документацией; названия полей `analytics_data.city` и `financial_data.cluster_*` в ответе v4 ещё не проверены на реальных данных.
- Адаптер написан по документации API и проверен на моках/демо; на живом аккаунте не запускался.
- Для товаров без категории в каталоге Ozon: «(без категории)».
